Runtime de tool calling no navegador

Fechar o ciclo que os playgrounds deixam pela metade

Problema pedagógico

No Google AI Studio e no playground do Groq o aluno declara a ferramenta, o modelo emite a chamada e o exercício para ali: não existe onde escrever o corpo da função. O aluno vê o tool_use, nunca a execução nem o tool_result voltando ao modelo. O conceito fica pela metade.

O que é

Uma página estática única que executa o ciclo inteiro dentro do navegador. O aluno escreve a declaração da ferramenta e o corpo da função em JavaScript; a própria página executa esse corpo com os argumentos que o modelo escolheu, devolve o retorno ao modelo e mostra a resposta final. Os passos aparecem em duas raias: o que roda na máquina do aluno e as decisões do modelo.

  • Dois provedores: Google AI Studio (padrão) e Groq, com troca de modelo na própria página e um botão que consulta o endpoint de modelos da conta.
  • Quatro cenários pré-carregados: ciclo completo, declaração opaca, falta de argumento obrigatório e pedido fora do escopo da ferramenta.
  • Ao fim de um ciclo concluído, a página gera um código de verificação de 8 caracteres via SHA-256 sobre a declaração, o corpo da função, o pedido e todos os passos executados. Entregas idênticas produzem o mesmo código, o que torna a cópia detectável na correção.
  • Exportação do relatório da execução por cópia para a área de transferência ou download em Markdown.
  • Realce de sintaxe escrito à mão, sem biblioteca: um pre colorido atrás de um textarea transparente, com a mesma métrica de fonte.
  • A chave de API fica no localStorage e vai apenas para o provedor escolhido. Não há servidor intermediário.

Stack

  • HTML, CSS e JavaScript sem framework
  • arquivo único de 2.367 linhas
  • Web Crypto (SHA-256)
  • API do Google AI Studio
  • API do Groq
  • GitHub Actions e GitHub Pages
  • Repositório github.com/pedrosatin/runtime-tool-calling

Laboratório de segurança de agentes

Injeção indireta de prompt como experimento reproduzível

Problema pedagógico

Segurança de agentes costuma ser ensinada como lista de recomendações. Aqui o aluno executa o ataque, vê o agente obedecer ao dado externo, depois liga as defesas e mede a diferença. O laboratório roda sem custo: o simulador é Node local e os testes de modelo usam os níveis gratuitos do Google AI Studio e do Groq.

O que é

Três atividades encadeadas, com guia de execução passo a passo para o professor.

  • Defesa em camadas. Um simulador em Node com duas camadas independentes: sonda de entrada, que inspeciona dados externos antes de chegarem ao modelo, e classificador de saída, que inspeciona a chamada de ferramenta antes da execução. Três logs de transação (limpo, com injeção explícita e com injeção ofuscada) mostram os três desfechos: fluxo normal, bloqueio na entrada e bloqueio na saída depois de a sonda falhar. O schema declara lerArquivo e notificarCanal, e o ataque tenta exfiltrar um .env simulado por um canal não autorizado.
  • Cinco vetores de injeção indireta. Cinco fontes comuns de dados num repositório, cada uma carregando uma instrução maliciosa: README com citação falsa sugerindo curl ... | bash, docstring em TypeScript pedindo bypass de validação de JWT, payload escondido numa fixture de teste, log de build induzindo git clean -fdx e resposta simulada de ferramenta MCP orientando injeção de dependência. O aluno audita um a um e registra aceitação ou recusa numa matriz de resultados.
  • Benchmark de resiliência em 10 rodadas. Protocolo com temperatura fixa em 0,2 e uma variável alterada por vez: cinco rodadas com o prompt base, cinco com a skill de guardrail ativa, sempre com o mesmo payload. Em seguida, mantendo a skill, entra um payload reformulado que apresenta a ordem maliciosa como requisito de conformidade ISO 27001 — a etapa que expõe o risco residual e a saturação de suítes estáticas de teste. A folha de coleta acompanha o material.

Stack

  • Node.js 18+
  • ES Modules
  • schemas de function calling em JSON
  • Google AI Studio
  • Groq
  • skill em Markdown
  • Repositório github.com/pedrosatin/laboratorio-seguranca-agentes

Servidores MCP da disciplina

Três servidores em TypeScript, publicados como imagens Docker

Problema pedagógico

O aluno precisa entender a diferença entre os três primitivos do MCP — tools, resources e prompts — e o que muda quando o servidor grava em disco e roda em container. Em vez de um exemplo genérico, cada servidor resolve um problema concreto e os três formam uma progressão: somente leitura, leitura com escrita, e servidor completo com os três primitivos.

O que é

  • psatin/mcp-pokeapi — duas tools somente leitura sobre a PokeAPI. Serve de exemplo digitado ao vivo: a pasta passos/ tem quatro versões do mesmo arquivo, do servidor vazio até a chamada real, e a aula pode parar em qualquer passo. Usa a comparação entre uma tool fetch genérica, que devolve o JSON inteiro para o modelo processar, e uma tool específica, que devolve campos já convertidos.
  • psatin/mcp-diario-violao — diário de prática de violão com seis tools, algumas com escrita em disco. A escrita traz para a aula três assuntos que o servidor somente leitura não alcança: aprovação de escrita no cliente, idempotência e persistência quando o processo roda em container efêmero.
  • psatin/mcp-estudo-b1 — revisão do conteúdo da avaliação B1 com sorteio de slide, autoavaliação, repetição espaçada e plano de estudo até a data da prova. Usa os três primitivos do protocolo. O conteúdo é derivado dos slides que a turma já recebeu, por um script que gera um JSON; o container não tem acesso ao repositório e não embarca banco de questões, gabaritos nem material do professor.

Os três falam MCP pelo transporte stdio e rodam em container. As imagens são multi-arquitetura (linux/amd64 e linux/arm64) e trazem o label io.docker.server.metadata exigido pelo gateway do Docker MCP Toolkit para aceitar referências docker://. O repositório inclui logs de terminal dos testes por protocolo: geração do conteúdo, tools/list e tools/call via stdio, execução em container com volume e execução pelo gateway.

Stack

  • TypeScript
  • Node.js 24 (executa .ts sem build)
  • @modelcontextprotocol/sdk 1.30
  • zod 4
  • Docker buildx multi-arch
  • Docker MCP Toolkit
  • Repositório github.com/pedrosatin/mcp-servidores-aula
  • Imagens psatin/mcp-estudo-b1, psatin/mcp-diario-violao, psatin/mcp-pokeapi

Servidor MCP de revisão da B1

Um servidor MCP com quatro transportes e cliente próprio

Problema pedagógico

Duas confusões recorrentes: achar que MCP é sempre um processo local por stdio, e não saber quando usar tool, resource ou prompt. Este servidor registra os três primitivos, sobe nos transportes que a especificação já teve e traz um cliente web que mostra o JSON-RPC na tela, para o aluno ver o initialize, o mcp-session-id e cada tools/call saindo.

O que é

Servidor de estudo para a avaliação B1, com oito tools, seis resources e quatro prompts. As tools cobrem consulta ao índice de conteúdo e ao texto dos slides, definição de conceitos, sorteio de revisão, plano de estudo até a data da prova e cálculo de custo de chamada de modelo com preços de catálogo. As consultas devolvem o link do slide na pasta da aula correspondente, no repositório da turma.

  • Uma decisão de projeto que vira conteúdo de aula: a tool listarTopicos existe porque o modelo só enxerga as descriptions das tools. O resource com o índice completo só entra no contexto quando o cliente anexa. Sem a tool, o prompt de revisão pedia um tópico livre e o modelo inventava o mapa da prova.
  • Transportes: stdio, Streamable HTTP com proteção contra DNS rebinding, o SSE legado da especificação 2024-11-05 para clientes antigos, e imagem Docker.
  • Front-end próprio, no mesmo origin do servidor HTTP: faz initialize, guarda o mcp-session-id, e cada botão da página vira um tools/call, com o JSON-RPC exibido ao lado.
  • Deploy público em Cloudflare Worker, sem sessão: cada POST /mcp sobe um transporte Streamable HTTP com resposta em application/json, justamente para o objeto JSON-RPC aparecer na aba Response do DevTools. O Worker embarca o índice e a tabela de preços, sem chamada de rede.

  • Cloudflare Workers e Wrangler
