Runtime de tool calling no navegador

Fechar o ciclo que os playgrounds deixam pela metade

Problema pedagógico

No Google AI Studio e no playground do Groq o aluno declara a ferramenta, o modelo emite a chamada e o exercício para ali. Não existe onde escrever o corpo da função. O aluno vê o tool_use e nunca vê a execução nem o tool_result voltando ao modelo.

O que é

Uma página estática única que executa o ciclo inteiro dentro do navegador. O aluno escreve a declaração da ferramenta e o corpo da função em JavaScript. A própria página executa esse corpo com os argumentos que o modelo escolheu, devolve o retorno ao modelo e mostra a resposta final. Os passos aparecem em duas raias, uma para o que roda na máquina do aluno e outra para as decisões do modelo.

  • Dois provedores, Google AI Studio (padrão) e Groq, com troca de modelo na própria página e um botão que consulta o endpoint de modelos da conta.
  • Quatro cenários pré-carregados: ciclo completo, declaração opaca, falta de argumento obrigatório e pedido fora do escopo da ferramenta.
  • Ao fim de um ciclo concluído, a página gera um código de verificação de 8 caracteres por SHA-256 sobre a declaração, o corpo da função, o pedido e todos os passos executados. Entregas idênticas produzem o mesmo código, o que torna a cópia detectável na correção.
  • O relatório da execução sai por cópia para a área de transferência ou download em Markdown.
  • Realce de sintaxe escrito à mão, sem biblioteca. Um pre colorido fica atrás de um textarea transparente, com a mesma métrica de fonte.
  • A chave de API fica no localStorage e vai apenas para o provedor escolhido. Não há servidor intermediário.

Stack

  • HTML, CSS e JavaScript sem framework
  • arquivo único de 2.367 linhas
  • Web Crypto (SHA-256)
  • API do Google AI Studio
  • API do Groq
  • GitHub Actions e GitHub Pages
  • Página pedrosatin.github.io/runtime-tool-calling
  • Repositório github.com/pedrosatin/runtime-tool-calling

Laboratório de prompt injection

Cada aluno recebe um caso e decide onde bloquear

Problema pedagógico

Segurança de agentes costuma ser ensinada como lista de recomendações. Aqui o aluno investiga um conteúdo externo, decide o destino da chamada de ferramenta e testa a própria decisão contra um modelo de verdade. Depois altera a política e observa o efeito da mudança no resultado.

O que é

Uma página estática que sorteia 1 entre 18 cenários. O sorteio mistura casos legítimos, ataques diretos e solicitações válidas com uma instrução maliciosa embutida. O caso permanece o mesmo durante a atividade inteira.

  • O aluno classifica o conteúdo, copia um trecho como evidência e escolhe entre permitir a chamada, bloquear na entrada, bloquear a ferramenta ou pedir revisão humana, com justificativa escrita.
  • Em seguida escreve a própria instrução para o Gemini, com os dados do caso anexados pela página, e compara a resposta do modelo com a decisão que tomou.
  • Depois altera a política de execução e roda o caso de novo, para registrar se o resultado mudou.
  • A entrega é um relatório gerado pela página, colado no formulário da atividade. A chave de API fica só na memória da aba e segue direto para a API do Google.

Stack

  • HTML, CSS e JavaScript sem framework
  • arquivo único
  • API do Google AI Studio
  • GitHub Actions e GitHub Pages
  • Página pedrosatin.github.io/laboratorio-prompt-injection
  • Repositório github.com/pedrosatin/laboratorio-prompt-injection

Extrator de diff de pull request

A mesma pull request revisada com três instruções diferentes

Problema pedagógico

O aluno precisa ver o que muda na revisão quando a instrução dada ao modelo muda, sobre o mesmo diff. Com o código à vista e a instrução variando, a diferença entre um pedido genérico e um roteiro de revisão com eixos declarados aparece no texto que o modelo devolve.

O que é

Uma página estática que busca o diff de uma pull request pública do GitHub e o prepara para revisão por um modelo. A extração usa o endpoint /repos/{owner}/{repo}/pulls/{number} com o cabeçalho Accept: application/vnd.github.v3.diff, que responde com CORS liberado. A página conta arquivos alterados, linhas adicionadas e linhas removidas, e mostra o diff colorido por adição, remoção, cabeçalho de arquivo e bloco @@.

  • Quatro saídas prontas para colar no modelo: pedido de revisão genérico, roteiro autoral com cinco eixos (corretude, paradigma funcional, segurança, performance e manutenibilidade), roteiro formal com resumo, tabela de impacto por arquivo e veredito, e o diff puro com os metadados.
  • Token pessoal do GitHub opcional, para escapar do limite de requisições anônimas e alcançar repositório privado.
  • Tudo roda no navegador. Não há backend e nem o token nem o diff ficam armazenados.

Stack

  • HTML, CSS e JavaScript sem framework
  • API REST do GitHub
  • GitHub Actions e GitHub Pages
  • Página pedrosatin.github.io/pr-diff-extractor
  • Repositório github.com/pedrosatin/pr-diff-extractor

Servidores MCP da disciplina

Dois servidores em TypeScript, publicados como imagens Docker

Problema pedagógico

O aluno precisa ver a diferença entre um servidor somente leitura e um servidor que grava em disco e roda em container. Cada servidor resolve um problema concreto e os dois formam uma progressão, leitura primeiro e escrita depois.

O que é

  • psatin/mcp-pokeapi tem duas tools somente leitura sobre a PokeAPI. Serve de exemplo digitado ao vivo. A pasta passos/ guarda quatro versões do mesmo arquivo, do servidor vazio até a chamada real, e a aula pode parar em qualquer passo. O exercício compara uma tool fetch genérica, que devolve o JSON inteiro para o modelo processar, com uma tool específica, que devolve campos já convertidos.
  • psatin/mcp-diario-violao é um diário de prática de violão com seis tools, algumas com escrita em disco. A escrita traz para a aula três assuntos que o servidor somente leitura não alcança: aprovação de escrita no cliente, idempotência e persistência quando o processo roda em container efêmero. O domínio vem do guitar-study, aplicação estática de estudo de violão com nove módulos, rotina diária e diário de prática.

Os dois falam MCP pelo transporte stdio e rodam em container. As imagens estão públicas no Docker Hub.

Stack

  • TypeScript
  • Node.js 24 (executa .ts sem build)
  • @modelcontextprotocol/sdk 1.30
  • zod 4
  • Docker buildx multi-arch
  • Docker MCP Toolkit
  • Imagens psatin/mcp-diario-violao, psatin/mcp-pokeapi
  • guitar-study pedrosatin.github.io/guitar-study

Prova de Programação Web em 2024

Um portal de notícias do IBGE como avaliação de bimestre

Problema pedagógico

Avaliar consumo de API pública com um enunciado fechado, com filtros por tipo, quantidade e período, sobre dados reais que mudam todo dia.

O que é

O código de exemplo da prova do segundo bimestre de Programação Web do 5º semestre, com o portal no ar. A página consulta notícias e releases no IBGE e filtra por tipo, quantidade e intervalo de datas.
